# Зависимости Brigade: ноябрь 2026

Исходная точка — `c78e669` (v0.65.5). Область проверки — прямые зависимости, инструменты сборки и peer dependencies во всех шести отслеживаемых `package.json`. «Было» и «стало» — разрешённые версии из lock-файлов, а не нижние границы диапазонов `^`. «Latest» — стабильный dist-tag npm на дату проверки, а не beta/next. Локальный `@brigade/plugin-ui` не имеет внешнего релиза в этом процессе.

## Что применить

Изменились фактические версии 29 разных прямых пакетов (33 записи с учётом повторов между проектами). Повышение нижней границы манифеста без изменения установленной версии сюда не входит.

1. **CAD: сравнение двух ревизий модели.** Для `<extra-model offset>` в model-viewer 4.4 можно явно задать миллиметры. Это подходит для режима «предыдущая / текущая»: наложить или разнести две GLB-модели, не меняя экспорт STEP и систему координат детали. Начать с переключателя для двух ревизий в CAD-плагине, а не во всех чатах. Само обновление библиотеки этот интерфейс не включает. [model-viewer 4.4](https://github.com/google/model-viewer/releases/tag/v4.4.0)
2. **Браузер сессии: держать Playwright и Chromium одной сборки.** В образе агента Chromium устанавливает именно локальный CLI Playwright. После обновления требуется новый образ; перенос старого браузерного кеша между версиями не заменяет сборку. Сохранить smoke-тест запуска браузера в Docker и добавить тест прохода через авторизованный proxy на контролируемом origin без логирования паролей. [Playwright release notes](https://playwright.dev/docs/release-notes)
3. **MCP: проверить вызовы без аргументов.** Обновлённый SDK корректно принимает `tools/call` без `arguments`. Добавить случай в протокольный smoke-тест встроенных MCP отдельно от вызова с пустым объектом. Переход HTTP-клиента на другой origin больше не разрешается по умолчанию; не включать его глобально ради отдельной интеграции. [SDK 1.32](https://github.com/modelcontextprotocol/typescript-sdk/releases/tag/1.32.0)
4. **Плагины: проверять готовый single-file HTML внутри MCP host.** В `vite-plugin-singlefile` появился сигнал о несовместимой CSP. Для Brigade правильная проверка — открыть готовый CAD-бандл в обычной изоляции приложения и убедиться, что сцена загрузилась без внешних JS/CSS. Не ослаблять CSP во всех плагинах. [Changelog singlefile](https://github.com/richardtallent/vite-plugin-singlefile/blob/59e8faa9ed8df908baf06b86101641d8abd73ca3/CHANGELOG.md)

## Миграция ACP-чата

ACP-чат переведён на AG-UI 1.x и assistant-ui 0.15. Цепочка обновляется целиком: клиент протокола, React runtime, адаптер и Markdown. Живая и архивная история импортируются одной функцией; для остановки серверного turn остаётся отдельный RPC. [AG-UI client](https://github.com/ag-ui-protocol/ag-ui/blob/main/sdks/typescript/packages/client/CHANGELOG.md) · [assistant-ui AG-UI](https://github.com/assistant-ui/assistant-ui/blob/main/packages/react-ag-ui/CHANGELOG.md)

Промежуточное обновление `@assistant-ui/react 0.14.29` требовало pin `@assistant-ui/tap 0.9.12`: с tap 0.9.26 эта комбинация входила в цикл рендеринга. На ветке React SDK 0.15 временный override снят; npm устанавливает одну копию tap 0.9.26.

Регрессии: `useAcpRuntime.test.tsx` проходит через настоящий HttpAgent и проверяет медленный Stop перед следующей отправкой, уход со страницы, восстановление permissions и повтор запроса после 401. Браузерный тест `scripts/screenshots/acp-runtime.test.mjs` открывает ACP-чат, отправляет сообщение, раскрывает группу инструментов и после refresh сверяет ленту без повторной отправки. RPC и ответы агента в нём подменены; это не проверка удалённого инстанса.

Для исправленного replay посреди фонового ответа в Docker обновить нужно не только Brigade: работающей сессии нужен новый демон. Старая сохранённая история не требует миграции; в архивном снимке можно показать только те части сообщения, которые в нём были записаны.

Ограничение Stop: RPC адресуется сессии, а не конкретному turn. В одной вкладке приложение дожидается отмены перед отправкой следующего вопроса. Две вкладки или два клиента не делят эту очередь: если один нажал Stop, а другой уже запустил новый turn, запрос отмены может остановить новый. Для гарантии между клиентами нужен идентификатор целевого turn на сервере.

## Что требует отдельной миграции

- **A2UI и MCP Apps не мигрировать одним bump Zod:** обе системы используют схемы на границе плагина, но требуют разные поколения Zod. В Apps 2 изменились npm API и peers, а не wire protocol; проверять совместимость старого CAD-бандла с новым host. Для A2UI 0.15 отдельно проверить v0.9-карточки, их тему и действия. [MCP Apps migration](https://github.com/modelcontextprotocol/ext-apps/blob/main/docs/migrate-to-2.md) · [React renderer](https://github.com/google/A2UI/blob/main/typescript/renderers/react/CHANGELOG.md)

- **Connect и Protobuf-ES v2:** поменялась модель генерируемых сообщений и сервисных дескрипторов; отдельный `protoc-gen-connect-es` больше не нужен. Это не независимые обновления четырёх строк npm: изменить `proto/buf.gen.yaml`, перегенерировать клиент и проверить создание сообщений, JSON и все Connect-вызовы. Go wire protocol менять ради этого не требуется. [Connect migration guide](https://github.com/connectrpc/connect-es/blob/main/MIGRATING.md)
- **Vite 8:** Rolldown/Oxc вместо прежних инструментов и другая нижняя граница поддерживаемых браузеров. Проверять web и одностраничный CAD-плагин отдельно, на CI-версии Node и в macOS WebView. Встроенное разрешение `tsconfig.paths` может убрать дублирование алиаса `@` в web-конфигурации; выгоду от перехода измерять на сборках Brigade. [Vite 7](https://v7.vite.dev/guide/migration) · [Vite 8](https://vite.dev/guide/migration) · [Возможности Vite 8](https://vite.dev/blog/announcing-vite8)
